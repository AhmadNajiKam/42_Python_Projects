# Contributing

Thank you for your interest in contributing to this repository!

This repository contains my solutions and experiments for the **42 School Python curriculum**. Contributions are welcome as long as they improve the correctness, readability, maintainability, or educational value of the project.

## Ways to Contribute

Contributions may include:

- Fixing bugs or incorrect implementations.
- Improving documentation.
- Correcting typos or grammar.
- Refactoring code to improve readability without changing behavior.
- Optimizing implementations while preserving the original project requirements.
- Adding or improving tests where appropriate.
- Improving development tooling or project structure.

Please avoid submitting complete alternative implementations unless they address a specific issue or significantly improve the existing solution.

## Before You Start

Before opening a Pull Request:

1. Search existing issues and pull requests to avoid duplicate work.
2. If your proposed change is substantial, consider opening an issue first to discuss the idea.
3. Keep each pull request focused on a single logical change.

## Development Workflow

1. Fork the repository.

2. Create a feature branch:

```bash
git checkout -b feat/short-description
```

Example branch names:

- `fix/ex02-parsing`
- `docs/improve-readme`
- `refactor/ex05-cleanup`

3. Make your changes.

4. Ensure that:

- The project behaves correctly.
- Existing functionality is preserved unless intentionally modified.
- Your code follows the existing style of the repository.

5. Commit your changes using a descriptive commit message.

Examples:

```text
docs: improve installation instructions
fix: handle empty input correctly
refactor: simplify parser implementation
```

6. Push your branch:

```bash
git push origin feat/short-description
```

7. Open a Pull Request describing:

- What changed
- Why the change was made
- Any relevant issue numbers

## Coding Guidelines

Please follow the existing coding style used throughout the repository.

In general:

- Keep functions small and focused.
- Prefer readable code over clever code.
- Use meaningful variable and function names.
- Remove dead or commented-out code before submitting.
- Keep changes consistent with the surrounding code.

## Documentation

Documentation improvements are always appreciated.

This includes:

- Explaining concepts more clearly.
- Adding examples.
- Correcting inaccurate information.
- Improving formatting and readability.

## Pull Request Checklist

Before submitting your Pull Request, please verify that:

- [ ] The project builds or runs successfully.
- [ ] Your changes have been tested where applicable.
- [ ] Documentation has been updated if necessary.
- [ ] Commit messages are clear and descriptive.
- [ ] The pull request focuses on a single logical change.
